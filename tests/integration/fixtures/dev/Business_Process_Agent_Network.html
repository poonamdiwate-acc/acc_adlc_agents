AI Job Portal — Business Process Agent Network

This diagram shows the service topology for the AI Job Portal platform.

graph TD
    LB[Load Balancer] --> API[API Gateway]
    API --> AUTH[Auth Service]
    API --> CANDIDATE[Candidate Service]
    API --> RECRUITER[Recruiter Service]
    API --> MATCH[AI Matching Service]
    CANDIDATE --> DB_CAND[(Candidate DB)]
    RECRUITER --> DB_REC[(Recruiter DB)]
    MATCH --> VECTOR[(Vector Store)]
    MATCH --> ML[ML Model Service]
    AUTH --> CACHE[(Redis Session Cache)]
    AUTH --> IDP[External: Identity Provider]
    CANDIDATE --> STORAGE[Object Storage - Resumes]
    RECRUITER --> NOTIFY[Notification Service]
    NOTIFY --> EMAIL[External: Email Provider]
    NOTIFY --> SMS[External: SMS Gateway]
    API --> MONITOR[Monitoring Agent]
    MONITOR --> METRICS[(Prometheus)]
    MONITOR --> LOGS[(Log Aggregator)]

Service Responsibilities

  • API Gateway: Single entry point. Rate limiting, request routing, TLS termination.
  • Auth Service: OAuth 2.0 token issuance, session management, RBAC enforcement.
  • Candidate Service: Registration, profile management, resume upload, application tracking.
  • Recruiter Service: Job posting, application review, candidate shortlisting.
  • AI Matching Service: Vector similarity search, ML-based role-candidate matching.
  • Notification Service: Email and SMS dispatch for application status updates.
  • Monitoring Agent: Health checks, metric collection, log forwarding, alerting.

External Interfaces (Trust Boundary Crossings)

  • Identity Provider (OAuth federation)
  • Email Provider (SMTP/API)
  • SMS Gateway (API)
  • Public Internet (via Load Balancer)

Data Flows

  • Candidate → API Gateway → Candidate Service → Candidate DB (sync, HTTPS)
  • Recruiter → API Gateway → Recruiter Service → Recruiter DB (sync, HTTPS)
  • AI Matching → Vector Store (sync, gRPC)
  • Auth Service → Redis (sync, TCP)
  • Notification Service → Email/SMS providers (async, queue-backed)
